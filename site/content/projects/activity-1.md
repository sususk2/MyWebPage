## 목적 {#purpose}

22.9kV 배전계통을 웹에서 단선도로 편집하면 전압·선로 과부하·역조류·단락전류 네 가지 시뮬레이션을 자동으로 다시 계산하는 플랫폼입니다.

계산 결과는 전압 pu, 선로 부하율 %, 고장전류 kA 같은 숫자로 나오기 때문에 전공자가 아니면 어느 구간이 왜 문제인지 알기 어렵습니다. 그래서 **결과를 진단 → 원인 → 해결책 순서의 글로 설명해 주는 AI 리포트**를 만드는 것이 목표였습니다. 이때 AI가 없는 수치나 설비를 지어내지 않게 하는 것이 가장 중요한 조건이었습니다.

## 수행 과정과 선택 이유 {#process}

1. **판정은 코드가, 설명은 AI가**  
   저전압·과부하·역조류 같은 문제 항목과 건강도 등급(정상·주의·위험)을 AI에게 맡기지 않고 코드가 먼저 계산해 "확정된 사실"로 넘겼습니다.  
   → 선택 이유: AI가 판정까지 하면 화면 진단표와 결과가 달라지거나 없는 문제를 만들어 낼 수 있기 때문입니다. AI는 확정된 사실을 풀어 설명만 합니다.

2. **출력 형식 고정**  
   AI 응답을 자유로운 글이 아니라 "진단 1개, 원인 목록, 해결책 목록" 형식(tool use)으로 받았습니다.  
   → 선택 이유: 화면의 카드에 그대로 나눠 보여 줄 수 있고, 형식이 틀리면 오류로 바로 알 수 있기 때문입니다.

3. **리포트는 버튼을 눌렀을 때만 생성**  
   → 선택 이유: 편집할 때마다 시뮬레이션이 다시 돌기 때문에, 매번 AI를 부르면 시간과 비용이 너무 많이 듭니다.

4. **쉬운 설명 개선**  
   실제 결과에 `CN_…` 같은 내부 이름과 MVA·kW 단위가 그대로 나와서, 용어 바꿔 쓰기 표와 "쉬운 설명 지침이 우선"이라는 규칙을 프롬프트에 추가했습니다.

## 결과물 {#result}

- 결과 화면에서 "AI 해설 만들기"를 누르면 진단·원인·해결책 카드가 표시됩니다.
- AI 리포트의 문제 판정 기준(단락용량 300 MVA 등)을 화면 진단표와 같은 규칙으로 맞췄습니다.
- 비전문가용 "쉬운 설명" 리포트가 현재 화면의 기본 설명 방식으로 쓰이고 있습니다.

## 배운 점과 개선 방향 {#lessons}

**배운 점**
- AI에게 모든 것을 맡기기보다, 확실한 계산은 코드로 하고 AI는 설명만 하게 나누니 결과를 믿을 수 있었습니다.
- 시험용 작은 데이터에서는 문제없던 기능이 실제 크기의 데이터에서는 시간 초과가 났습니다. 실제 데이터로 확인하는 단계가 꼭 필요하다는 것을 배웠습니다.

**한계와 다음 개선**
- 쉬운 설명이 잘 됐는지는 아직 사람이 직접 읽고 판단합니다. → 같은 입력으로 여러 번 생성해 내부 이름·단위가 섞이지 않았는지 확인하는 점검 목록을 만들 계획입니다.
- 계통이 커지면 응답이 느려집니다. → 프롬프트에 넣는 표를 문제가 큰 항목 위주로 더 줄여 응답 시간을 낮출 계획입니다.
