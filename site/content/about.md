## 자기소개 {#intro}

안녕하세요, **최민준**입니다. 데이터를 사람이 이해할 수 있는 설명으로 바꾸는 일에 관심이 있습니다.

캡스톤 팀 프로젝트 '배전계통 통합 분석 플랫폼'에서 시뮬레이션 결과를 AI가 진단·원인·해결책으로 설명하는 **AI 리포트 기능**을 맡았습니다. 이 사이트에는 제가 배운 것과 직접 한 일을 정리합니다. 작업 기록은 [GitHub(sususk2)](https://github.com/sususk2)에서 볼 수 있습니다.

## 관심 분야 {#interests}

**데이터 분석** — 숫자로 된 결과에서 "무엇이 문제이고 왜 그런지"를 찾아 설명하는 일

관심을 갖게 된 이유:
캡스톤에서 배전계통 시뮬레이션 결과는 전압(pu), 선로 부하율(%), 고장전류(kA) 같은 숫자로만 나왔습니다. 같은 숫자라도 어떤 기준으로 나누고 어떤 순서로 보여 주느냐에 따라 문제를 찾는 속도가 크게 달랐습니다. 저전압·과부하 같은 판정을 코드로 먼저 정리하고 나서야 설명이 정확해지는 것을 보며, 데이터를 정리하고 해석하는 과정 자체에 흥미가 생겼습니다.

## 학습 목표 {#goals}

**목표: AI가 만든 결과의 품질을 검증하는 방법 익히기**

AI 리포트를 만들면서 "결과가 맞는지, 쉬운 말로 잘 설명됐는지"를 아직 사람이 직접 읽고 판단하고 있다는 한계를 느꼈습니다.

다음 행동:
1. 캡스톤 AI 리포트의 점검 목록 만들기 — 내부 이름(`CN_…`)·단위가 섞였는지, 등급이 화면 진단표와 같은지, 프롬프트에 없는 수치를 썼는지
2. 같은 시뮬레이션 결과로 리포트를 여러 번 생성해 점검 목록으로 비교하고, 통과율을 기록하기
3. 점검 중 일부(내부 이름·단위 포함 여부, 등급 일치)를 Python 코드로 자동 확인하기

## 역량과 사용 사례 {#skills}

숙련도보다 실제로 써 본 경험을 기준으로 적었습니다.

- **Python** — 캡스톤 `ai_report/report.py`에서 시뮬레이션 결과로 저전압·과부하·역조류를 판정하고 프롬프트를 만드는 코드 ([대표 활동](../projects/activity-1/#process))
- **AI API·프롬프트 설계** — Claude·Gemini API로 리포트 생성, 출력 형식(진단·원인·해결책) 고정, 쉬운 설명 지침 개선
- **Git·GitHub** — 캡스톤 팀 저장소에 Pull Request(#4, #6, #8)로 작업 반영, 이 사이트의 커밋·push 관리
- **Hugo·Markdown·GitHub Actions** — 이 포트폴리오 사이트 제작과 자동 배포 ([저장소](https://github.com/sususk2/MyWebPage))
- **AI 코딩 도구 (Claude Code)** — 구현할 내용을 정해 요청하고, 결과를 실행·확인한 뒤 팀 코드에 반영할 범위를 결정
